## G119 - OAuth in the system browser (the container Android actually uses)

Operator asked: *"for google cant we use the part needed from an android version to make the webview
looked like an android phone ?"* Then: *"what do you recomand ?"* -> *"alright lets go"*.

**The evidence that changed the design.** `client/www/js/cordova-standalone-shim.js` shims
`window.cordova.plugins.browsertab`, i.e. cordova-plugin-browsertab = a **Chrome Custom Tab** on
Android. The Android build never disguises its WebView; it leaves it for a real browser. Our shim
routed that call into an in-app WebView2 popup -- the one container Google refuses for sign-in
(`disallowed_useragent`, matched on the `wv` marker) and the one its signup verification scores as an
unknown device. So the *architecture* was transplanted, not the fingerprint. Phone emulation rejected
explicitly: UA is one signal of many (client hints, userAgentData, touch, WebGL are computed from the
real platform), the mismatch is itself a bot signal, and the deciding signal (datacenter egress, no
Google cookies) is untouched.

**What was built** (5 pieces, no page code):
- `RuntimeSettings.OauthBrowser` (off by default) + a checkbox on the settings page.
- `WebView2ClientForm.OpenOAuthDialog`: when on, `OAuthBrowserHandoff.Open(url, instanceId, log)` ->
  `Process.Start(UseShellExecute)`; the popup stays as the fallback.
- `OAuthBrowserHandoff.EnsureProtocolHandler`: `HKCU\Software\Classes\dofustouch` = `"<exe>" "%1"` +
  `URL Protocol`; re-registered per process because the app can move.
- `Program.WriteDeepLinkRequest` + `DeepLinkFromArgs`: the handler starts a SECOND process and the
  single-instance mutex would drop the URL, so argv is written to `oauth_deeplink.txt` (atomic
  MoveFileEx) **before** the mutex decides.
- `MainForm.DeliverDeepLink`: the existing 1 s launch-request poller reads it and calls
  `window.__onDeepLinkCallback(url)` on the client that opened the browser
  (`OAuthBrowserHandoff.TakePending`, 15 min). With several clients and nothing pending it logs
  "no client is waiting for it; dropped" rather than guessing -- a code to the wrong client is a
  wrong account.
- `uninstaller.cs` deletes the protocol key.

**Verified.** `test_oauth_system_browser` 10 checks; 6 mutation anchors all CAUGHT
(`scratch/mut_oauth2.log`); `DofusFarm.exe --oauth-selftest` exit 0 on this machine -- handler
registered, `URL Protocol` set, command `"C:\Users\sao\Documents\dofus-emu\DofusFarm.exe" "%1"`,

### Built: `ai/conformal.py` + `ai/test_conformal.py` (30 tests, ~1.3 s)

Split conformal, score `1 - p(y|x)`, quantile rank `ceil((n+1)(1-alpha))` (the exact integer --
`ceil(n(1-alpha))` is the off-by-one that voids the guarantee at small n). Prediction set
`{j : p_j >= 1 - q_hat}`; accept only when the set is a **singleton**; empty or ambiguous both
abstain. `per_class=True` gives Mondrian class-conditional quantiles. CLI writes the artifact.

**Measured on real data** (`data/tool_sft_v3/val.jsonl`, 3,719 rows, 42 features, through
`models/backups/tool_policy.807023112a4b.onnx`, argmax accuracy **0.9043**), calibrate on one
half, measure on the other:

| alpha | floor | coverage (target) | set | abstain | empty |
|---|---|---|---|---|---|
| 0.05 | 0.132 | 0.9425 (0.95) | 1.19 | 0.136 | 0.000 |
| 0.10 | 0.333 | 0.9011 (0.90) | 0.99 | 0.020 | 0.013 |
| 0.20 | 0.791 | 0.7946 (0.80) | 0.83 | 0.173 | 0.173 |

Guarantee holds at all three. At alpha=0.10 the gate escalates 2.0% of decisions and **1.3% are
an empty set** — the model's top answer does not survive its own calibration. Those are the
confidently-wrong decisions a scalar threshold cannot name. Per-class q_hat at alpha=0.10 ranges
0.489 (class 4, n=576) to 1.000 (every class with n=1), so the corpus skew makes
class-conditional coverage the thing to watch.

Wiring is **additive and off by default**: `GuardPolicy.conformal = None`, new
`set_conformal()` / `gate_choice()` / `choose_gated()`; `choose_from_logits` and `choose` are
byte-identical (verified: rule path resolves, ungated argmax unchanged).

To fit the production artifact: the shipped head is 266-wide and builds features at runtime in
`agent/planner_nn.py`, so its calibration needs a labelled run, then
`python -m ai.conformal --probs cal.npz --check test.npz --out models/conformal.json`.
