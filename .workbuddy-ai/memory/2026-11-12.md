### What the map actually is

So the wall ring is the geometry. `_agentBorderCells` (the page's geometric fallback, G110) reads

The running client is still `2026-11-10a`, so it does not even have that fallback.

### The defect
Not the missing exit. The sentence `"map %s publishes no crossable border; ask the server for the
%s neighbour %s"` was produced in **two** places: `_indexed_crossing_ask` (bounded by
`CROSSING_ASK_LIMIT`, counted by `_travel_call`) and an inline copy in `_travel_ask` with its own
rotation and neither budget nor refusals. The live run used the copy: 7 asks in one goal, `left` at
steps 7/8/12 and `bottom` at 6/9. And `last_nav.stage` — the field that says the crossing is
impossible — was read by nothing (G111's shape, one layer out).

### Fixed
- `_travel_ask` now calls `_indexed_crossing_ask`; the duplicate rotation is gone (pinned by a
  source check: one producer of the sentence).
- `QuestPlanner._refused_borders(obs, here)` + `NAV_WALL_STAGES = {change_requested_no_cell,
  change_requested_at_edge}`; walk stages excluded on purpose (a blocked path is retryable).
- `self._walls: {from_map: {(direction, to_map)}}` — a wall is a property of the **map**, so a
  second objective cannot restart one the first spent.
- `_indexed_crossing_ask` no longer calls `_note_crossing`; `_travel_call` owns that count and the
  border was being charged twice per ask (spent after one retry). Found by replaying a snapshot.
- Sealed map prints once: `[planner] map 146277376 has refused every border it publishes (...)`.
- Loop: the unplannable branch now advances `self._index` (four rows had carried index 17) and sets
  `ended_because` (the run had said "goals exhausted" with three objectives ready and sixteen
  retired).
