## Session 3 — serving-path defect fixed (biggest win of the night)

Root cause of the 92.9%->77.7% drop through `choose()`: **459 of 800 val rows in one
contiguous block were `hdv.list {item, price_rule:"fixed"}` with no price** — goals
like "put X on the market" state no price, the model still emits `fixed`, and the
cross-parameter rule (`fixed needs an integer price`) rejected the whole call,
discarding a correct tool choice and a correct item span over one optional field.

Fix: `ai/postprocess.py` step 8 drops `price_rule` when it is `fixed` and `price` is
not an int. Dropping is not guessing a price — the schema default applies, which is
what the gold label does. A goal that states a price keeps the rule.

Measured (INT8, full splits, serving path with postprocess + resolvers):

|---|---|---|
| val call | 0.663 | **0.812** |

| gold call | 0.718 | 0.718 |
| val_indist call | 0.893 | 0.897 |

Invalid calls across 2,273 sampled val rows: 481 -> 14. INT8 vs fp32 delta on call:
**+0.000** everywhere; latency 60 ms vs 151 ms.

## Session 8 — auto-update fix (blocks live play)

Symptom: launching shows "a new version is available, restart?" and the user cannot play.

Investigated, in this order:
- `build/script.js` (the game bundle) has **no** version-update popup — the only
  `updateRequired` hits are UI refresh flags, `newVersion` is IndexedDB.
- The host (`desktop/*.cs`) has no such dialog; its "restart" strings are renderer
  and instance restarts.
- The only restart-on-update path is the app shell: `js/autoupdate.js::check()` ->
  `loader.update(false)` -> `cordova.fireDocumentEvent('sourceUpdated')`. In the
  original Android build a Java layer handled that event and showed the dialog.
  This host has no Java layer, so the prompt is either native from that path or
  from the CDN manifest being newer than the local mirror.

Fix applied in `client/www/js/autoupdate.js::check()`:
- on `hasUpdate`, **apply it and reload once** instead of firing `sourceUpdated`;
  guarded by `sessionStorage.autoUpdateApplied` (max 2) so a server advertising a
  build it does not serve cannot loop the client;
- logs `[AUTOUPDATE] manifest version ... server ...` so the decision is visible;
- `localStorage.skipUpdateCheck = '1'` bypasses the whole check.

Also added **console capture** to `__DofusRecorder` (`_hookConsole`, levels
log/info/warn/error, 500-char cap, recursion-guarded) so the next launch records
what the loader decided — the dialog is native, the cause is a console line.

Rebuilt (DofusFarm.exe 412,160 bytes, setup 284.4 MB, 11 client patches).
Unknown still: whether the prompt comes from this loader or from Ankama's server
rejecting the client version (hardcoded default `3.14.2` / `3014002` in
`standalone.html`, `WebView2Backend`, `farmengine`; `DynamicVersionResolver`
queries Play and can override it). The trace will say which.

## Session 9 — the real login blocker (found in the trace)

The play trace from the user's attempt (`trajectories/play_dofus-05.jsonl`, 69 lines)
showed the actual failure, not the one I guessed:
- console: `connectionManager.disconnect: reason=LOGIN_ERROR` at 04:05:00, then a
  page reload at 04:05:10, then `[Auth] Skipping auto-login: already used this
  session (post-logout reload)` — forever.
- root cause in `WebView2ClientForm.cs` (guest auto-login injection):
  `sessionStorage.setItem('dfGuestLoginDone','1')` was set **before**
  `playWithGuest()`, so a single failed login permanently disabled auto-login for
  that tab. The client then sits on the login screen, which is where the
  "new version / restart" prompt lives.

Version theory **disproved**: `assetsVersions.json` (no params) returns
`assetsVersion 3.3.9 / staticDataVersion 1.43.17` = exactly what the client uses,
and the cached app version 3.14.3 (resolved from Play at 03:57) matches the Play
listing. So it is not a version mismatch.

Fix: replaced the eager flag with a retry budget — `dfGuestTries` (max 5) +
`dfGuestLastAt` (20 s minimum gap), a success watcher that logs
`[Auth] Guest login succeeded as <name> (id N)`, and an attempt counter in the
console line. Rebuilt: DofusFarm.exe 414,208 bytes.

Also this session: `autoupdate.js` had been edited only in `client/www`, while the
runtime serves **`desktop/client/www`** (WebView2ClientForm.cs:666). Synced, and
`builder/Build.cs` now copies `client/www/js/autoupdate.js` ->
`desktop/client/www/js/` on every build so the two cannot drift again.

Still open: whether the guest account `[GUEST]59d5210dfdbd35e99` (5th line of
accounts.txt) is simply expired. If LOGIN_ERROR repeats 5x, that is the answer —
