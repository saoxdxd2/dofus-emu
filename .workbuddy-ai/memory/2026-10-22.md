## Session 8 — auto-update fix (blocks live play)

Symptom: launching shows "a new version is available, restart?" and the user cannot play.

Investigated, in this order:
- `build/script.js` (the game bundle) has **no** version-update popup — the only
  `updateRequired` hits are UI refresh flags, `newVersion` is IndexedDB.
- The host (`desktop/*.cs`) has no such dialog; its "restart" strings are renderer
  and instance restarts.
- The only restart-on-update path is the app shell: `js/autoupdate.js::check()` ->
  `loader.update(false)` -> `cordova.fireDocumentEvent('sourceUpdated')`. In the
  original Android build a Java layer handled that event and showed the dialog.
  This host has no Java layer, so the prompt is either native from that path or
  from the CDN manifest being newer than the local mirror.

Fix applied in `client/www/js/autoupdate.js::check()`:
- on `hasUpdate`, **apply it and reload once** instead of firing `sourceUpdated`;
  guarded by `sessionStorage.autoUpdateApplied` (max 2) so a server advertising a
  build it does not serve cannot loop the client;
- logs `[AUTOUPDATE] manifest version ... server ...` so the decision is visible;
- `localStorage.skipUpdateCheck = '1'` bypasses the whole check.

Also added **console capture** to `__DofusRecorder` (`_hookConsole`, levels
log/info/warn/error, 500-char cap, recursion-guarded) so the next launch records
what the loader decided — the dialog is native, the cause is a console line.

Rebuilt (DofusFarm.exe 412,160 bytes, setup 284.4 MB, 11 client patches).
Unknown still: whether the prompt comes from this loader or from Ankama's server
rejecting the client version (hardcoded default `3.14.2` / `3014002` in
`standalone.html`, `WebView2Backend`, `farmengine`; `DynamicVersionResolver`
queries Play and can override it). The trace will say which.

Also found: `[OAUTH-POPUP] CONTINUE click failed: Object reference not set to an
instance of an object` — a NullReferenceException in the popup handler after the
code already arrived (harmless to the flow, but a real crash path).

- the client's registry is `cm.eventHandlers` (confirmed by the probe), and we

- the login path uses `cm.send`, and we only wrapped `sendMessage`;
- writeback always assigned `_handlers` even when we wrapped another slot.
All three fixed: wrap `sendMessage` **and** `send`, read `eventHandlers`, write
back to the slot actually wrapped, report which slot in `hook_report`.

Next run's trace will contain `IdentificationFailedMessage` with its **reason
byte**, which distinguishes BAD_VERSION from BAD_CREDENTIALS — that decides

## Session 35 — autopilot, market model correction, network-change resilience

**The market model was wrong and is now fixed.** "A sale" is not one controllable
action: you can list, you cannot make a buyer appear. Controllable = read the price,
list an item you own, manage listings. So the kamas loop is *supply*, not revenue.
`agent/autopilot.py` records a successful listing as `listing_open` (state=open) and
never as kamas earned; `test_autopilot_listing_is_not_revenue` pins it. Buying is
forbidden outright (`FORBIDDEN_TOOLS = {"hdv.buy"}`).

**Price resolution is now real, not a dangling rule name.** Prices never arrive with
the scan: `ObjectAveragePricesMessage {ids[], prices[]}` (~55 KB, whole server) and
`ExchangeBidHouseInListAddedMessage {objectGID, prices[], quantities[]}` come later.
`__PriceCache` in mobile-disguise.js absorbs them in the recv hook (before the
6000-char recorder cap truncates them), `hdv.scan` answers from cache, and
`hdv.list` resolves `median_minus_1`/`undercut` from it and reports `price_source`.
`fixed` without a price is refused. Schema enum is `median_minus_1|undercut|fixed`
— note there is no `average_minus_1`; a test caught that mismatch.

**`agent/autopilot.py` — the AI runs alone.** observe -> choose -> guard -> execute
-> label -> decide. Stop conditions: step budget, minutes, `--stop-file`, 3
consecutive failures, 3 identical no-progress calls. Writes
`trajectories/autopilot.jsonl` with verdict (advanced/noop/failed/blocked), latency,
cell/map. Those verdicts are the second agent's labels. `--dry-run` verified end to
end; not yet run against a live instance.

RulePolicy gained a narrow listing intent (`_RE_LIST_MARKET`: needs both a listing
verb and a market word, so "list my quests" is not a sale) plus quantity extraction
("put 3 bread on the market" -> quantity 3).

**Ethernet broke the login with "server busy".** Root cause: WARP drops its tunnel
on any network change and sits in "Connecting"; the proxy used to `os.Exit(2)` when
the upstream was down, so a 40 s tunnel gap became a dead instance. Fixed:
- proxy keeps listening and keeps failing closed (port open so the host's 5 s probe
  succeeds and no in-process fallback starts), logs the outage, and a background
  watcher logs when WARP returns;
- per-dial retry (3 attempts, ~4.5 s) so a blip does not surface as a reload;
- `farmengine.EnsureUpstreamAlive` runs `warp-cli mode proxy` + `connect` when the
